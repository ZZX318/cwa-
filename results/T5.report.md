# T5 报告：w=4 航道数双峰原因（只读探针）

## 结论

**【已验证】** w=4 时 `n_lanes` 呈双峰（约 206–218 vs 恒为 384）的根因是 **`2w = 8 m = ha_orchard` 名义行距 `row_spacing`**：偏移相位决定「每行 1 条满载航带 + 行间稀疏条带」还是「每行被 2 条满载航带双覆盖」。

- **高峰（384）**：`offset ≈ w/2`（CSV 中 1.857–2.150；对应全部 B-boundary，以及 U=4 的 S_h）。24 条航带均含 16 段 → `24×16=384`。
- **低峰（~210）**：`offset ≈ 0` 或 `≈ w`（CSV 中 0 / 0.01–0.15 / 3.857–3.902；对应全部 S1，以及 U=2 的 S_h）。约 12 条对正树行的满载带（各 16 段）+ 行间因 jitter 擦边产生的稀疏段 → ~206–218。
- `fixed_y_lanes` 对**无冠层相交**的条带 `continue` 跳过；行间条带因 `jitter_xy=0.4` 与冠层半径常仍有 1–5 段，故 **`strip_count` 并非减半**（约 23–24），减半的是满载段数。

假设原文「2w = 8 m = 行距」成立，且可在 CSV 偏移与内存重放 `fixed_y_lanes` 上逐条对齐（seed0：S1/B/S_h×U 四处 `n_lanes` 与探针一致）。
