# 侧风缓冲压到树冠：网页可复现案例

这版完成“敏感区输入 → 上风侧缓冲 → 禁喷裁切 → 关喷连接 → 覆盖评价”，并增加航带平移对照入口。它不是真实药液漂移预测，也没有自动求最优相位。

## 1. 网页操作

启动项目后打开网页（本次验证服务 http://127.0.0.1:8813/）。旧服务需要重启后刷新，避免 Python 后台仍缓存旧模块。

1. 展开 **02 · 单机作业计划**，点 **加载侧风压树样例（替换当前场景）**。
2. 默认使用 **CAW 顺序优化**，保持航带平移为 **0 m**，点 **生成航线**。
3. 在 **03** 把覆盖网格改成 **0.1 m**，点 **查看最终覆盖**，等评价完成。
4. 回到 **02** 把航带平移改为 **0.49 m**，重新生成；再去 **03** 查看最终覆盖。
5. 两次分别保存计划。**04** 五算法比较使用当前同一平移值；它比较转场与顺序，不会自动替代步骤 2–4 的相位对照。
6. 要改敏感区、距离或风，展开 **风与敏感区缓冲**，修改后点 **按当前风重新生成缓冲**，再规划。风变化未应用时，后台拒绝用旧缓冲规划；编辑距离或原区未应用时，网页拒绝继续。

## 2. 案例几何

- 20 棵树，4 排 × 5 棵，每排树冠半径 1.5 m，喷幅 2 m。
- 原始敏感区为 x∈[23,24]、y∈[0,22] 的矩形，红色虚线显示原区。
- 来向 π rad 表示从 −X 吹向 +X。演示风速 2 m/s，**人为指定缓冲 3.5 m**。
- 最终禁喷矩形为 x∈[19.5,24]、y∈[0,22]，黄色显示。新增部分是原区以西 3.5 m 的区域，压到了最后一排树冠。
- 本例不能由“2 m/s”推导出“3.5 m”。距离是可替换的实验输入，需要论文另给文献或实测依据。

## 3. 树冠冲突怎么处理

树不会被删除。落在禁喷范围内的树冠属于受限面积，保持关喷；范围外仍属于可喷任务。规划器按完整喷幅裁切，不只检查飞机中心点。转场允许关喷飞越禁喷区，遇禁飞区仍绕行。

当前固定 Y 的零相位锚点是全部目标树冠的最小 X，**不是地块边界锚定的论文 B 基线**。本例锚点 x=1，禁喷前沿 x=19.5。零相位下跨越前沿的喷幅被禁止，区外仍有一小块树冠未覆盖。向 +X 平移 0.49 m，使相邻合法喷幅右边缘到 x=19.49，保留 0.01 m 间隙，避免接触即违规的数值判据。

平移参数适用于共享条带的固定 Y 和三个 CAW；naive 不采用条带相位。平移 0 保留原有规划行为；非零平移采用完整喷幅的平移格网并向左补一条，以免地块另一端凭空失去覆盖。增加航带/喷洒段可能增加时间。

## 4. 实测数值

以下为固定 Y 对照存档；若复现此表，请先切换为 **固定 Y**。默认 CAW 的最新结果见 caw-phase-results.json。以下是 **0.1 m 网格**结果，时间为当前分段恒速模型估算：

| 指标 | 原条带（0 m） | 平移条带（0.49 m） |
|---|---:|---:|
| 受限树冠面积 | 31.80 m² | 31.80 m² |
| 约束外额外漏喷 | 4.00 m² | 0.00 m² |
| 可喷树冠覆盖率 | 96.41% | 100.00% |
| 全部目标覆盖率 | 75.00% | 77.79% |
| 足迹违规 | 0 | 0 |
| 估算作业时间 | 85.78 s | 124.22 s |

总覆盖没有达到 100%，因为受限树冠仍然不喷。平移方案更慢，不能宣称全面优于原方案。

网格对照：0.25 / 0.1 / 0.05 m 下，原条带额外漏喷分别为 3.75 / 4.00 / 3.875 m²，平移后均为 0。**采样为 0 不等于连续几何严格为 0**，尤其本例留有 0.01 m 间隙，尚需闭式冠层交面积或更细网格核验才能写成论文的精确结论。原始结果见 phase-results.json。

## 5. 实现口径与限制

- 缓冲距离从喷洒足迹边缘量起，不是从飞机中心量起；规划时的半喷幅检查不能再被当成第二次经验漂移距离。
- 上风向偏移为 d·(cos θ, sin θ)。最终使用原区及偏移区扫掠的轴对齐包围盒，与现有规划器/评价器的保守口径一致。矩形加正交风时为精确方向扩展；斜风或非矩形会过度保守，不能称为精确漂移边界。
- 静风不增加方向缓冲，只保留原区包围盒；这只是当前数值模型约定，不代表静风没有漂移风险。
- 原区与生成区分别存入 scene.wind_buffer，最终约束写入 no_spray_zones。重复应用替换旧生成区，不叠加距离，保留手工禁喷区。越出场景范围会报错，不会偷偷截断保护区；请调整距离或先扩大场景。
- 若直接编辑生成的黄色区，系统会要求重新加载原场景后重建，防止静默覆盖人工修改。
- 喷头仍为即时开关，没有 τ 滞后；不能用这个样例证明 τ>0 时的论文主张。
- 正式论文仍需真实的 B 锚定、边带补喷/改航向等竞争对照。这里提供能跑通的工程入口，不替代公平实验。

## 6. 文件与回归

- base.scene.json：原始场景；buffered.scene.json：包含原区来源、风参数和最终约束的场景。
- baseline.job.json / shifted.job.json：两套作业参数。
- baseline.plan.json / shifted.plan.json：两套真实规划结果。
- phase-results.json：三个网格下的对照。
- five-shifted.comparison.json：平移 0.49 m 下的五算法真实对照。

独立回归：`python -B -c "from wind_buffer_checks import run; run()"`。
全量回归：`python -B main.py --check`。

## 地图敏感区与自动恢复入口

1. 在 02 选择“风吹向”，设置风速；在“风与敏感区缓冲”中设置实验缓冲距离。
2. 点顶部工具栏“敏感区”，在地图逐点画保护对象，按 Enter 或点击首点闭合。自动生成红色原始边界与黄色最终保护范围；支持撤销/重做，保存场景时来源与生成区一并保存。重复画可增加多个敏感区。修改原区坐标可使用高级 JSON，再应用缓冲。
3. 切换风吹向或提交风速/自定义来向，会重算已有敏感区缓冲并使旧航线失效。若扩展越出场景范围则保留旧几何并提示错误，后台禁止拿旧缓冲与新风参数规划。
4. 点“计算区外漏喷恢复方案”。系统在同一保护范围下，用 CAW 默认 NN+2-opt / 时间目标 / 1 m 路由网格，比较当前相位、区域边界附近相位和少量均匀相位。优先减少额外漏喷，再比较时间。有改善时自动应用相位并生成真实航线；去 03 查看最终覆盖。
5. 当前限制：最多 200 个目标、16 个候选相位，评价网格 0.05–1 m；不是全局联合优化。当前只自动实现航带平移，没有自动实现边带补喷或航向旋转。

### 被扩展范围压到的树怎么办

- 原始敏感区及最终保护范围内的树冠：保留树和受限面积记录，当前条件下关喷。不能为提高覆盖率直接取消缓冲。可待风况变化后依据同一参数依据重评，或另行评估人工定点作业。
- 树冠在保护范围外的部分：仍是喷洒任务。恢复入口比较航带平移，尽量减少连带漏喷；无法改善时明确显示剩余面积与后续可评估的方案。
- 如果当前网格下全部树冠都被限制：明确提示没有合法喷洒面积及待处理建议，不伪装成全覆盖成功。
- 原区附近没有树：仍需生成保护范围，因为敏感区代表需要保护的对象，不由树是否存在决定；恢复入口可能返回当前无额外漏喷。

本例点击一次恢复入口，0.1 m 网格下自动选出约 0.49 m，相位前后额外漏喷 4.00 → 0.00 m²，受限面积均为 31.80 m²，估算时间 85.96 → 121.23 s。连续几何的小面积余漏仍需更精细验证。
